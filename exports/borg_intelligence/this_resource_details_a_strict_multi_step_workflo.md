## 🧠 Technical Summary
The technical resource outlines a rigid two-step workflow for an 'orchestrating agent' (ORCHESTRATOR ONLY). The core principle is strict separation of duties: the orchestrator never interacts directly with files or code. Step 1 involves spawning a 'Research & Spec' subagent to analyze the codebase and generate documentation in a specific 'docs/SubAgent docs/' directory. Step 2 involves spawning an 'Implementation' subagent, which receives the path to the generated specification file and performs the necessary coding changes. Crucially, the orchestrator must use a default subagent tool (`runSubagent`) and strictly avoid using any specific agent names, such as 'Plan'.

## 🛠️ Key Features
Strict agent role definition, Mandatory sequential two-step workflow (Research -> Implement), Forced delegation of read/write operations to subagents, Standardized documentation path for intermediate artifacts, Explicitly forbidden self-execution/file reading by the orchestrator.
