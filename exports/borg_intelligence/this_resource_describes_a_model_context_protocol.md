## 🧠 Technical Summary
The `meta-mcp-proxy` functions as a centralized intermediary layer, often referred to as a 'meta-MCP' or wrapper, to manage a collection of other MCP servers or local computational tools. Its primary technical approach involves implementing a form of local Retrieval Augmented Generation (RAG) over the available tools. It achieves this by providing LLMs with two core methods: 'discover' and 'execute'. The 'discover' method utilizes fuzzy matching against tool descriptions (which can be augmented via `discoverDescriptionExtras`) to select the most relevant tool, thereby reducing the context window necessary for the LLM. The 'execute' method acts as a straightforward proxy, routing the request to the correctly identified remote MCP server (executed via `command` and arguments) or executing a registered local JavaScript function. Configuration allows defining remote servers via standard execution commands, environment variables, and communication transport (defaulting to stdio).

## 🛠️ Key Features
Unified Tool Discovery Across Servers, Proxy Execution Routing, Fuzzy Matching for Tool Selection, JavaScript Function Exposure as Tools, Configurable Server Definitions, Context Reduction via Discovery.
