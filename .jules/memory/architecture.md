## Architecture & Patterns
- **Web App Architecture**: The project relies on a Flask backend for heavy data processing and API requests (`app.py`). The WSGI application object must be instantiated at the module level (e.g., `application = create_app()`) to ensure compatibility with web servers like Gunicorn, especially for deployments on cloud platforms like Render. A high-speed Node.js/Express layer exists to serve the React/Vite frontend.
- **LLM Integrations & Resiliency**: The system leverages multiple LLM providers (e.g., Gemini, OpenRouter, LM Studio) to conduct data research and extraction. To manage quotas, rate limits, and fallback scenarios gracefully, it uses specialized connection pools like `GeminiModelPool` and `MultiProviderPool`.
- **Database Strategy**: It uses a unified SQLite database architecture (`bookmarks.db` and `metamcp.db`) located at the project root to store parsed bookmark data, agent states, and other system information. Centralized deduplication is handled via scripts like `deduplicator.py` and `master_sync.py`.
- **Ingestion Pipeline**: The asynchronous research pipeline (`resume_research.py` and `deep_research.py`) reads links from `bookmarks.txt`, processes them using the LLM pools, and stores the categorizations in the SQLite database. Progress and failures are meticulously tracked using `deep_research_status.json` and `failed_bookmarks.txt`.
- **Dependency Management**: Standard `requirements.txt` is used for Python dependencies (e.g., `google-genai`, `anthropic`, `openai`, `beautifulsoup4`, `Flask`). Node.js UI layers require separate `npm install` in `bobbybookmarks-ui/server` and `bobbybookmarks-ui/client`.
- **Testing Methodologies**: Pytest is employed extensively, utilizing `unittest.mock` to mock LLM calls. Asserts on mocked logger methods (like `logger.warning.assert_any_call`) are designed to be flexible because the exact warning strings might be dynamic depending on the active fallback mechanisms.

## Operational Procedures & Decisions
- **LLM Authentication**: To run the ingestion pipeline locally with multiple providers, it's necessary to export corresponding API keys (`OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`) before executing the research scripts.
- **Retrying Ingestions**: If any links fail during ingestion, they are appended to `failed_bookmarks.txt`. To retry these links in subsequent runs, the file must be cleared manually (e.g., `> failed_bookmarks.txt`).
- **Deployment Compatibility**: Gunicorn expects the Flask instance to be exposed at the module level. For example, `gunicorn app:application` demands that `application = create_app()` is placed outside the standard `if __name__ == "__main__":` block.
- **"Don't Stop the Party" Directive**: The project adheres to a strict operational directive: never terminate active background processes (such as workers, servers, daemons like `deep_research.py` and `auto_pulse.py`) unless absolutely necessary, to prioritize autonomous and continuous operation.
- **Comprehensive Documentation**: The repository maintains a robust suite of documentation files (e.g., `VISION.md`, `MEMORY.md`, `DEPLOY.md`, `CHANGELOG.md`, `VERSION.md`, `ROADMAP.md`, `TODO.md`, `IDEAS.md`, `HANDOFF.md`, `GLOBAL_RULES.md`, `AGENTS.md`) to capture all project context.
- **Version Control as Source of Truth**: The version number is strictly maintained in `VERSION.md`. Every build bumps this version number, and the corresponding Git commit message must explicitly reference the version string bump.
- **Deep Commenting**: Code must be commented in deep detail, explaining the 'what', 'why', side effects, optimizations, and alternative methods considered, unless the code is completely self-explanatory.
